# Закрытая статистика владельца

Страница `/owner/statistics/`: день/месяц, сегодняшний итог, итоги месяца, график, модели, категории, поиск и CSV. Периоды UTC соответствуют сохранённому `day`; преобразовать старые записи в местную дату без времени события нельзя.

## Защита

Отдельный Worker `tegroup-statistics-dashboard`. Отчёт отдаёт только агрегаты, без event_id и данных покупателей. Вход по одному email и паролю; Cloudflare Access и банковская карта не требуются.

`OWNER_EMAIL` — переменная Worker. `OWNER_PASSWORD` — зашифрованный Secret Cloudflare, уникальный длинный пароль (16–256 символов; рекомендуется случайный пароль из менеджера паролей). Секрет задаёт владелец самостоятельно в Cloudflare, он никогда не попадает в Git, клиентский код или логи. При смене email/пароля все прежние сессии становятся недействительными.

Подписанная HMAC-SHA256 сессия действует 12 часов. Ключ отделён от пароля SHA-256 с контекстной меткой. Cookie `__Host-te_stats`: Secure, HttpOnly, SameSite=Strict, Path=/. В cookie нет email или пароля. Вход и выход требуют same-origin POST. Проверка владельца выполняется до запросов к D1. Отсутствующая конфигурация закрывает доступ (503), отсутствующая/неверная сессия даёт 401 API или редирект на вход для страницы.

`LOGIN_LIMITER`: 10 попыток в минуту на кабинет в каждой точке Cloudflare. Это приблизительный распределённый лимит платформы, не глобальный точный счётчик. Лимитер не хранит IP, email или пароль; ключ фиксированный. При отсутствии/ошибке лимитера вход закрыт. Все ответы private/no-store, CSP закрывает сторонние скрипты и встраивание. Статистика не хранится в localStorage. Workers.dev, preview URLs, логи и трассировки выключены. Клиентское оформление остаётся без регистрации.

Выход удаляет cookie в текущем браузере; скопированная ранее сессия действует до истечения 12 часов. Для отзыва всех сессий смените Secret OWNER_PASSWORD.

## Развёртывание

1. Применить безопасный индекс к существующей D1: `CREATE INDEX IF NOT EXISTS document_events_day ON document_events(day);`.
2. Создать Worker `tegroup-statistics-dashboard`. Привязать существующую D1 как `STATS_DB` (см. wrangler.dashboard.jsonc).
3. Добавить Rate Limiter `LOGIN_LIMITER`, namespace `2026102401`, limit 10, period 60.
4. Указать согласованный владельцем email в `OWNER_EMAIL`; сам владелец создаёт Secret `OWNER_PASSWORD`. Не публиковать значения в репозитории.
5. `npm ci --prefix server/document-stats`, `npm run build --prefix server/document-stats`, `node tests/stats-dashboard.mjs`. Сборка `dist/dashboard.mjs` готова для редактора Cloudflare; Wrangler использует wrangler.dashboard.jsonc.
6. Подключить маршрут `tegroup.cc/owner/statistics*`; отключить workers.dev, preview URLs, логи/трассировки. Сборщик `/api/document-events` не изменяется.
7. Проверить отказ публичному `/report`, страницу входа, неверный пароль и лимит. Владелец входит самостоятельно, затем проверяются его агрегаты, переключение периодов и выход.

## Что считается

Одно событие — один успешно сформированный комплект. Повторный download, preview и два инвойса не считаются новыми событиями. Предложения с одинаковыми названием модели и категорией объединяются; один договор с двумя предложениями одной модели даёт 1 оформление этой модели. Разные модели одного договора увеличивают соответствующие строки, но общий итог комплектов остаётся 1. Закрытие формы и создание нового комплекта — новое событие. Подписание/оплата не отслеживаются.

## Проверки

`node tests/document-stats.mjs` — сборщик, дедупликация, отказ при персональных данных.
`npm run build --prefix server/document-stats && node tests/stats-dashboard.mjs` — пароль, tampering/expiry/rotation сессии, CSRF, лимитер, закрытый API, пустые периоды, високосный месяц, несколько моделей и одна модель в нескольких предложениях.

Локальное превью и скриншоты вне репозитория, в deliverables/private-dashboard-2026-10-24. Превью использует отдельную SQLite в памяти и вымышленные данные. Обход авторизации существует только в локальном сервере превью; HTTP-переключателя обхода в опубликованном Worker нет.
