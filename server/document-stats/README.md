# Учёт сформированных комплектов

Включён 24 октября 2026 года (МСК). Cloudflare Worker `tegroup-document-stats`, D1 с тем же именем. Клиент подключён в разделах cars/equipment, `TEDocumentStatsEnabled=true`.

Считается успешное создание всего комплекта PDF. Это не доказательство подписания, оплаты, покупки или резерва. Исторических событий до запуска нет: прежняя версия работала только в браузере. Тестовые PDF не являются обращениями клиентов.

В базе только случайный идентификатор события, день по Москве (Europe/Moscow, UTC+3), его часовой пояс и публичные идентификаторы предложений. Повтор отправки с тем же идентификатором не увеличивает счётчик. Оба инвойса, скачивания и повторные просмотры не создают отдельных событий. Оформление заново после закрытия формы является новым событием. Заказ с несколькими позициями даёт один комплект и по одному событию на каждую модель. Система без авторизации даёт статистику интереса; намеренная имитация клиентских событий возможна. По этим счётчикам нельзя автоматически объявлять технику проданной.

Имена, телефоны, e-mail, реквизиты, VIN, номера договоров, цены, PDF и IP в БД не записываются. Worker не ведёт собственные журналы запросов; инфраструктура Cloudflare всё равно обрабатывает сетевые метаданные. Не включать Workers Observability с телами запросов.

## Развёртывание

1. Создать D1 `tegroup-document-stats`, применить `schema.sql` и `model-report.sql`.
2. Записать настоящий database_id в wrangler.jsonc; привязать `STATS_DB`.
3. Развернуть Worker и маршрут `tegroup.cc/api/document-events`. Маршрут требует проксируемого домена Cloudflare. Сам сайт остаётся на GitHub Pages.
4. Проверить POST, повтор POST, запрет GET и отсутствие покупательских данных. Удалять только явно помеченные тестовые события.
5. Подключить `/assets/document-stats.js` в cars/equipment, включить `window.TEDocumentStatsEnabled=true` в отдельном конфигурационном скрипте и обновить уведомление о технической статистике. Выполнить production build с SRI.

Клиентская интеграция в document-flow вызывает `record` только после успешной генерации; при отсутствии скрипта или выключенном флаге работает прежний сценарий.

## Просмотр владельцем

Доступ к числам — только через авторизованную консоль D1. Публичного GET/API отчёта нет.

```sql
SELECT day, offer_id, generated_document_sets
FROM model_daily_statistics ORDER BY day DESC, generated_document_sets DESC;
```

```sql
SELECT model, offer_id, generated_document_sets, last_day_utc
FROM model_statistics ORDER BY generated_document_sets DESC;
```

Названия моделей показаны в `model_statistics`; справочник — `catalog.json`. При изменении ассортимента обновлять allowlist Worker и представление `model_statistics` из этого справочника. Общее число комплектов — `SELECT COUNT(*) FROM document_events;`; сумма по моделям может быть больше из-за комплектных заказов.

Проверка: `node tests/document-stats.mjs`.

Прямой доступ владельца: https://dash.cloudflare.com/7995c2fc571d0fa3622f1eb84309f72d/workers/d1/databases/5c6cd632-11d6-4044-86d7-00051fc6eb19/console

Рабочий маршрут только `/api/document-events`; workers.dev и preview URL выключены. Логи и трассировки Worker выключены. Обработчик не читает cookies, IP и Referer. Статистика не блокирует генерацию или скачивание при недоступности сети. Непереданное событие может потеряться после закрытия страницы: фонового хранилища/идентификатора посетителя нет.

## Переход на московские дни — 26.10.2026

Перед обновлением обоих Worker применить `migrations/0001_moscow_days.sql` один раз. Проверить `PRAGMA table_info(document_events)` перед применением. Старые строки сохраняют `day_timezone=UTC` и прежний день: времени в них нет, точная перекладка невозможна. Новые строки получают день `Europe/Moscow`; повтор с тем же event_id не меняет ни день, ни часовой пояс. Отчёт/CSV показывают МСК и отдельное пояснение о старых датах. Период по умолчанию и автоматическое обновление переходят через московскую полночь; выбранный исторический период не переключается. Время в БД по-прежнему не сохраняется. Днём оформления считается день первой успешной регистрации события сервером, а не локальные часы покупателя.

Проверка границ дня, месяца и года, миграции и дублей: `node tests/statistics-timezone.mjs`.

## Произвольные периоды

Кабинет поддерживает день, месяц, 7 дней по выбранную дату (`mode=week&period=YYYY-MM-DD`) и диапазон включительно (`mode=range&from=YYYY-MM-DD&to=YYYY-MM-DD`). Поиск и CSV используют загруженный период; при ошибочных датах или незавершённой загрузке другого периода выгрузка отключена. Для диапазонов длиннее 90 дней график группируется по месяцам; общий итог, таблица моделей и CSV охватывают весь выбранный диапазон.
